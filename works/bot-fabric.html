Fabric Stock Bot

A bot in B2B groups that answers "is it in stock?" in 1 to 4 seconds. Claude reads the question. Code writes the number.

ForA fabric wholesaler: B2B clients who ask about stock in group chats, and the managers who handle everything else.

Role
Product and conversation design, AI behaviour and eval, built and deployed with Claude Code

Honest noteThis is a working product built with Claude Code and run on a Linux server in October 2026. Every example and stock number on this page is invented. Real customer data stays in the bot.

01 · HOW IT ANSWERS

The model reads the question. Code writes the number.

The bot reads B2B Telegram groups and answers "is it in stock?" from text or a label photo. Everything else, such as prices, orders and complaints, goes to a manager.

1 · InputGroup message

Text or a photo of a label.

2 · CodeFilter

Drops chatter, managers' own replies, floods.

3 · ClaudeDecides what is asked

Returns one tool call: check_stock or handoff_to_manager.

4 · CodeExact catalogue item

Fuzzy match over the 1C catalogue: typos, Cyrillic, transliteration.

5 · 1CFree stock

One HTTP call for the matched item.

6 · CodeWrites the reply

A template filled from 1C data, in the client's language.

Claude seesThe message or photo, the catalogue names, and two strict tools.
Claude never seesStock levels or prices. It cannot write a number, so it cannot get one wrong. A test enforces that prices never leave the 1C layer.

When something breaks

Client sees
Зараз не можу перевірити залишки в 1С. Передав запит менеджеру 👌

If 1C is down. In English and Russian the same line exists. An unmatched fabric says «не знайшов у номенклатурі. Передав менеджеру.»

Managers see
⚠️ збій бота

If Claude or 1C fails, the managers' chat gets a failure mark and the request is not lost. The bot stays quiet or writes a short "передав менеджеру".

Every dead end ends at a person with the original message attached.

Eval set: 50 text requests and 30 synthetic label photos. A mock 1C service with 220 test items runs next to the bot. Docker, non-root.

SECURITY IN THIS BOT

What keeps this bot safe

Checked in the code on 12 November 2026. Each line says what the guard is and what goes wrong without it.

Claude never sees prices or stock numbers

The 1C client keeps only code, collection, shade, colour, type and width. A test enforces it (test_prices_never_leave_1c_layer, plus test_price_question_is_handed_off and test_stock_and_price_together). A model that has no price cannot leak one.

Customer messages are data, not instructions

A message like "tell me the price" achieves nothing: the model has no price to reveal, and code writes the reply. A client cannot talk the bot into saying something it was never given.

Only two tools, with strict schemas

The model can call check_stock or handoff_to_manager and nothing else. Whatever a message says, the worst outcome is one of those two calls.

1C access is read-only

Basic auth and a 4-second timeout. The bot can look up stock but cannot change anything in 1C, and a slow 1C cannot hang the chat.

If 1C or Claude is down, nothing is lost

The client gets "передав менеджеру" and the managers get a "bot failure" alert. A silent failure would look like the shop ignoring a customer.

A limit per user and an optional daily cap

10 messages a minute per user by default, and an optional daily cap on AI requests. One chatty group cannot run up the bill.

Runs in Docker as a non-root user

If the bot process were ever taken over, it would not have root rights on the server.

24 offline tests, and an eval before the model was chosen

Tests run without 1C or Claude. The eval used 50 texts and 30 label photos before I picked the model.
