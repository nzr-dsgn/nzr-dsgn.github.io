What the client gets

  • Service, master, day, time, confirm. Every step is a button, and "any free master" shows the most slots.
  • Reschedule or cancel up to 3 hours ahead. If a slot is taken in the meantime, the bot says so and offers another.
  • A reminder the evening before (confirm, reschedule, cancel) and another 2 hours before.
  • A waitlist, loyalty on every Nth visit, referrals and prepayment by card.
  • After the visit, a 1 to 5 rating. 4 or 5 asks for a Google review. 1 to 3 goes straight to the owner.

What the staff gets

Every request lands in the staff group as a card with Take, Cancel and Complete. Nobody has to ask who is on it.

SECURITY IN THIS BOT

What keeps this bot safe

Checked in the code on 12 November 2026. Each line says what the guard is and what goes wrong without it.

Mini App sign-in is checked with HMAC-SHA256

Telegram signs the data it gives a Mini App. The bot rebuilds the signature from a key derived from its own token, compares it in constant time, validates the user object and ends the session after 2 days. Without this check, anyone could open the owner panel by sending someone else's Telegram id.

Payment callbacks need a valid signature

WayForPay tells the bot that a deposit was paid. Without the signature check, anyone could post a fake "paid" message and get a booking marked as paid.

Instagram webhooks need a valid signature

Without it, a stranger could send fake Direct messages or comments to the bot and trigger bookings or replies.

Parameterised SQL

User text goes into queries as values, never as query text, so a client who types SQL into a name field only gets a strange name. Where a column name has to be dynamic, it must come from a fixed whitelist.

All user text is escaped before it enters a Telegram HTML message

An esc() helper is used at about 175 call sites. A client who types an HTML tag in their name gets that text shown as typed. It cannot change how the owner's message looks.

Staff and owner actions check the user id

Cards in the staff group show Take, Cancel and Complete to everyone in the group. The bot compares the user id with the configured owner and staff ids before it acts.

Tokens and keys come from environment variables

No secret is in the code, and an .env.example lists what is needed. Sharing or backing up the code never leaks a key.

Sending retries with backoff, and the bot never closes a visit on its own

If Telegram fails, a message waits and tries again instead of vanishing. A visit drives bonuses and money, so the bot only reminds staff and a person closes it.

Still to harden in this bot

  • No automated tests yet. Next: tests for payments and booking slots.
  • Versions were kept as .bak files on the server. Next: git with a private remote and checks on every push.

Server-wide measures and the full audit are in How I keep all four safe.
